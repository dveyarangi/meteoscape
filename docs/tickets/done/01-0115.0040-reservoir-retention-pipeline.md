## Acceptance criteria

- [x] The pipeline is live in both positions (the stores themselves were wired inert at slice 3);
      a Source's units stay keyed by the **native** Z cell, the root's by the request's vantage.
- [x] Read-back answers on the request's own geometry: a value held at a grid tick and a native
      height is returned addressed to the asked point and vantage, with its values and provenance
      unchanged — and the relabel is a single **`TODO (temporary)`** site owned by
      [0117](./01-0117-off-grid-homogenization.md), not a loosened crop.
- [x] A parameter the child does not serve is **omitted** from the answer, not raised on (the
      read-back folds over what is *held*, never over what was asked); a request where the child
      serves **nothing** is a `CapabilityMismatch`, matching the Arbiter's verdict.
- [x] A fully-fresh repeat request is served with **no** provider call (0112's day-anchoring makes
      same-day full-horizon repeats identical).
- [x] A request whose Z differs from a prior one **reuses** stored native units rather than
      refetching.
- [x] A stone-cold mixed request (direct parameters + calculator inputs) issues **one** vendor
      fetch; the Calculator's input `Selection` is served from the store; same `issue_time` across
      all assembled parameters — the Calculator's inputs are fresh in the store, and a boundless
      ask has no coverage to fail (RFC 0014 d.5).
- [x] A temporal miss or window-extension refetches the **whole unit** single-origin end-to-end
      (old window discarded; the refetched unit lands the provider's full live timeline).
- [x] The `Arbiter` never serves stale entries; the retention interval only bounds memory.
- [x] Per-unit freshness is honored as `Reservoir` policy: an unexpired unit serves with no trip,
      an expired one triggers refill (differing expirations mocked — a single-cadence source's
      units age together); a held window that does not cover the required one refetches the whole
      unit (covers vs extension vs disjoint — moved here from slice 3, 2026-08-09).
- [x] Integration tests cover fresh-serve, per-parameter refill (mocked expirations), and
      whole-unit single-origin refetch — **split by what each level can actually reach** (narrowed
      at review, 2026-08-09): the **mocked-transport** e2e covers fresh-serve and
      expiry-triggered refetch, while per-parameter divergent expirations and whole-unit
      replacement are pinned at the **node** level, where the expirations can be mocked apart. A
      single-cadence transport ages its units together, so the respx path cannot manufacture
      divergent expirations at all — the reason the parent ticket says *mocked* in the first place.

## Align resolutions (plan-impl 2026-08-09)

- ~~Stages 2 (source) and 3 (root) as separately landable greens?~~ **No** — one `Reservoir`
  class turns both positions on together, and the e2e `call_count` flip needs both (shared source
  warm + root serve). **Merged into one "pipeline live" stage**; source vs root criteria remain
  as test groups inside it. Read-back helpers stay a prior green stage; docs/landing stay last.
- ~~Stage-1 read-back test entry while `project` is still pass-through?~~ **Private methods on
  `Reservoir`** (`_relabel_onto`, `_read_back`); tests construct a `Reservoir` and call
  `_read_back` with a hand-built `CoverageSet`. No public read-back API, no test-only hook.
- ~~`ground` / `agreed_geometry` `ValueError` in `_read_back`?~~ **`RuntimeFailure`** — admission
  and the store already decided these units answer this ask; a failure here is an engine
  invariant, not an unservable request. Not `CapabilityMismatch` (that mapping is the leaf's).
