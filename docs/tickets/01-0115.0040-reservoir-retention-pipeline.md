## Acceptance criteria

- [ ] The retentive `Store` is wired into both positions with its private lattices (unit keys carry
      the native Z cell).
- [ ] A fully-fresh repeat request is served with **no** provider call (0112's day-anchoring makes
      same-day full-horizon repeats identical).
- [ ] A request whose Z differs from a prior one **reuses** stored native units rather than
      refetching.
- [ ] A stone-cold mixed request (direct parameters + calculator inputs) issues **one** vendor
      fetch; the Calculator's input `Selection` is served from the store; same `issue_time` across
      all assembled parameters.
- [ ] A temporal miss or window-extension refetches the **whole unit** single-origin end-to-end
      (old window discarded; the refetched unit lands the provider's full live timeline).
- [ ] The `Arbiter` never serves stale entries; the retention interval only bounds memory.
- [ ] Per-unit freshness is honored as `Reservoir` policy: an unexpired unit serves with no trip,
      an expired one triggers refill (differing expirations mocked — a single-cadence source's
      units age together); a held window that does not cover the required one refetches the whole
      unit (covers vs extension vs disjoint — moved here from slice 3, 2026-08-09).
- [ ] Mocked-transport integration tests cover fresh-serve, per-parameter refill (mocked
      expirations), and whole-unit single-origin refetch.
