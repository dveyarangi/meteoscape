*Amended 2026-08-09 (align):* the store-side `report` verb dissolved — the store's public face is

## What to build

~300–400 raw lines (002/003b-scale; the largest slice, kept whole because a half-store serves
nothing):

- **`quantize`** — `ground`'s store-side sibling in fold shape (read the request-side verb
  first), a **store method** whose context is constructor state: a per-axis fold delegating to
  `Axis.clip`; latticed X/Y resolve to the containing cells' **ticks**, unit-deferred axes (T, Z)
  take `ANY`, anything else identity → parent, *quantize is ground's store-side sibling*
  (including the #22/#23 deferrals and their escape hatch). Its only public job is authoring the
  refill fetch-order; `project` runs the same fold internally on raw asks.
- The **`MemoryStore`**: unit-granular (`(parameter, per-axis cells, window)`), private lattices
  (spatial from `StoreSpec`; T inherited from answers), `capability` = **holdings narration**
  ([#47](../concerns.md#47-a-stores-capability-narrates-plural-holdings-truncate-to-one-reach)),
  `project` = the **holdings query** — the held units at the asked cells as a `CoverageSet`, each
  record carrying its own domain and provenance; asked-but-unheld parameters **omitted**, empty
  answer normal, **stale included** (the contract is clockless and freshness-blind — freshness is
  the reader's policy; [ADR-0006](../adr/0006-materialization-granularity-and-store-shape.md)) —
  and `assimilate` consuming the answer and slicing per parameter inside the store → parent,
  *`assimilate` consumes the answer*.
- **Retention interval** honored (housekeeping only — the one clock use, substrate-private, never
  part of the `Store` contract) and the retentive `StoreFactory` honoring the configured
  `StoreSpec` and the position-derived `deferred` axes.
- **`StubStore` deleted; `MemoryStore` wired for real, inert by construction** — the pass-through
  `Reservoir` never touches its store, so behavior is unchanged and slice 4 touches only the
  `Reservoir` (2026-08-09 pass 2).
- Refill *ask construction* stays slice 4's; this slice authors no `SelectionDomain` beyond its
  tests.

## Acceptance criteria

- [ ] Given the timeline unit definition, `quantize` produces boundless T/Z and the containing
      X/Y cells' **ticks as pinned point members** (the cell's span never leaves the store; a tick
      re-quantizes to itself); given an inverted (grid-style) unit definition, the same fold
      produces the inverted ask — no axis role is hardcoded.
- [ ] `assimilate` accepts a multi-domain answer and the store afterwards holds units keyed by
      the answer's native cells; a guard test fails if any module outside the store references its
      private unit or lattice types.
- [ ] `project` accepts **raw asks** — the store translates onto its boxes internally, and a
      request and its own fetch-order select the same units: held parameters return as records on
      their native domains with their provenance intact (expired provenance included — no
      freshness filtering); asked-but-unheld parameters are omitted; a cold store answers an
      empty `CoverageSet`; nothing raises for absence.
- [ ] `capability` narrates holdings: honest parameter membership, per-parameter reach = the
      latest-assimilated unit's domain (plural holdings truncate —
      [#47](../concerns.md#47-a-stores-capability-narrates-plural-holdings-truncate-to-one-reach));
      an empty store advertises no parameters.
- [ ] After re-assimilation exactly one window per unit exists, single-origin — a spliced
      `valid_time` is unrepresentable (whole-unit replace, never merge).
- [ ] Units older than the retention interval are evicted on write and read; after eviction,
      `project` and `capability` no longer answer them.
- [ ] All of the above is demonstrated by store-level tests; the wired graph carries
      `MemoryStore`s inert (`StubStore` gone), and the full existing suite stays green with no
      behavior change.
