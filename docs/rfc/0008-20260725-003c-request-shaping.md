**Scope in one line:** the MCP edge parses optional `start`/`end` into **raw UTC instants** and
authors a `SelectionDomain` whose T is `SnappedAxis(bounds)` — resolution, landed at m4, serves
`bounds ∩ the winner's live window` on the winner's own lattice — narrates the relative horizon
and reach, and deletes `Settings.default_horizon`. All inside the surface adapter; **zero engine,
provider, or manifold change**.

## Facts that shape the implementation (verified 2026-08-05)

1. **`validate_calculators` is already `weave`'s first step** (`nodes/weaver.py`;
   `test_server.py` asserts the startup `CompositionError`). The ticket's compose()-step criterion
   stays **already landed**; no change (carried).
2. **m4's vocabulary is landed and pinned.** `SnappedAxis`, `SelectionDomain`, `ground`, and
   per-kind `clip` live in `manifold/domain.py`; `RollingAxis.clip` materialises the live window
   (`manifold/cadence.py`); the leaf resolves snapped end to end (`TimelineProvider`). And
   `fakes.snapped_point_domain(start=…, end=…)` **is the edge's production shape with the T axis
   swapped** — verified at m4 against `build_selection`'s own X/Y/Z construction — so this
   migration is a T-axis swap on a shape already pinned. `serialize_coverage`'s `GridDomain`
   requirement is satisfied by construction: `ground` builds exactly that (also verified at m4).
3. **`SnappedAxis` validates at construction**: `ValueError` on a naive-datetime edge or reversed
   bounds (`__post_init__`, `domain.py`). `Interval` itself validates **nothing** — it stores
   bounds as given — so the ordering check cannot be delegated to construction of the interval.
   The edge parses to aware-UTC and pre-checks ordering, so a caller mistake surfaces as
   `bad-request` — never a naked `ValueError` escaping the tool.
4. **The bare-date probe is still required** (carried facts 5–6): `datetime.fromisoformat`
   silently parses `"2026-07-20"` as midnight, so `date.fromisoformat` probes **first** —
   succeeding means a bare date (week dates too, same probe), rejected with guidance; only on its
   `ValueError` fall through to `datetime.fromisoformat`. Python 3.14 accepts the `Z` suffix.
5. **The narrated horizon is invariant** (carried): a `RollingAxis` extent length is `max_lead`
   whenever it is read, which is what makes the relative narration true for the process lifetime.
6. **The omitted-`end` default is the first request to touch the conservative-cadence edge, and it
   resolves to 384 ticks.** With Open-Meteo's `CadenceDef` (Δ = 1 h, latency 1 h, `max_lead`
   16 d): `A = floor(now, 1h) − 1h`, and the resolver serves `[floor(now), A + 16 d]` on its
   hourly lattice — `(A + 16 d − floor(now)) / 1 h + 1 = 384` regardless of `now`. Deterministic
   tests derive the count **from `CADENCE`**, never hardcoded without the derivation comment
   (carried fact 2, re-derived for the snapped path).
7. **Two clock reads per request are benign under snapped — trivially, not by an interleaving
   proof.** The edge reads `now` (implicit `start`; the live reach fold for an omitted `end`); the
   winner's `RollingAxis.clip` reads its own clock at resolution. Staleness only moves the
   *bounds*, and resolution's intersection trims — the clamp-era containment analysis
   (superseded fact 7) has nothing left to prove. **And the production "raw now" is already
   hour-floored by the clock itself**: `Metronome.now()` floors to its `resolution` (1 h default,
   `clock.py`) — the edge does no flooring, but the instant it receives in production is the
   current hour tick. `StoppedClock` can sit mid-hour (`test_mcp_app.py`'s clock is 12:34), which
   is how deterministic tests exercise the raw rule directly.
8. **A vendor delivering fewer ticks than declared is an honest shorter answer, not a fault.**
   "Shorter is honest" is mode-split (m4; [edge/provider.md](../edge/provider.md)): a snapped ask
   grounds against the delivery, so there is nothing to fall short of — and after this ticket the
   edge issues **only** snapped T. The old decision-4 symptom table changes accordingly: trailing
   nulls at the 16-day edge → honest nodata; a clamped/short vendor response → shorter
   `valid_time`, disclosed; only a vendor **400** is a fault. Systematic edge rejection is fixed by
   **cadence tuning** per [#18](../concerns.md#18-clock-anchored-footprint-fidelity), never edge
   code.
9. **Call-site inventory.** `build_mcp_app(gateway, clock, <horizon>)` — **eight sites**:
   `server.py`, `tests/deterministic/test_e2e_forecast.py`, `tests/deterministic/test_server.py`,
   `tests/deterministic/test_server_smoke.py`, `tests/parity/test_open_meteo.py`, and **three
   tool-level sites in `tests/deterministic/api/test_mcp_app.py`** (positional `_HORIZON` —
   invisible to a `default_horizon=` grep, which is how an earlier count missed them).
   `build_selection(default_horizon=…, envelope=…)`: the seven construction sites in
   `test_mcp_app.py`. Mechanical: drop the horizon argument, swap `envelope=` → `capability=`.
   The smoke site (`test_server_smoke.py`) is also the **empty-menu pin** — its `_EmptyView`
   carries an empty `UnionCapability`, so it is the existing test that proves startup does not
   raise when there is nothing to narrate.

## Design decisions

Numbering continues the 2026-07-25 staging so the trail stays citable: 1, 3, 5 are carried; 2 is
superseded (→ [§Superseded approach](#superseded-approach-the-clamp-record)); 4 is carried
re-aimed; 6–8 are the re-stage's own.

1. **Carried, landed** — the compose()-validation criterion is satisfied by existing code (fact 1).
2. **Superseded** — the edge-clamp rule set; record preserved in
   [§Superseded approach](#superseded-approach-the-clamp-record).
3. **Carried** — an explicitly empty `parameters` list is `bad-request`
   (`"parameters must not be empty; omit it to get all served parameters"`); `None` keeps meaning
   "all served". An empty **resolved** set (the no-provider profile) is
   `CapabilityMismatch("profile serves no parameters")` at the edge, **before** the reach fold,
   which is undefined over zero parameters.
4. **Carried, re-aimed** — the omitted-`end` default probes the conservative-cadence edge **live at
   landing** (stage 5): the post-003c parity run is the acceptance probe for the 384-tick default.
   The symptom table is fact 8's; the contingency (cadence tuning, owned by
   [#18](../concerns.md#18-clock-anchored-footprint-fidelity)) is unchanged.
5. **Carried** — bounds are ISO **datetimes only**; bare dates (and week dates) are rejected loudly
   with the fix in the message. Accepted cost unchanged: one self-healing round trip for an agent
   that sends a bare date.
6. **The edge authors raw bounds and holds no tick arithmetic.** T is
   `SnappedAxis(Interval(start_instant, end_instant))` — no `_Bound` instant/tick pair, no
   `floor_to` on bounds, no `ceil_to`, no servable-range computation; the resolver's grid supplies
   anchor and step ([ADR-0002](../adr/0002-data-model.md)). Ordering is checked on **raw
   instants**, with implicit `start = now` when omitted — where `now` is whatever the injected
   `Clock` returns (fact 7): the production `Metronome` floors to the hour, so implicitly-started
   requests behave in production exactly as the clamp draft's `floor(now)` reference did — an
   `end` anywhere in the current hour admits and yields the one current tick; only a
   finer-resolution clock would surface the raw-instant difference. `start == end` is the legal
   single-instant ask. **Messages, pinned:** a stated backwards pair →
   `f"start is after end ({start!r} > {end!r})"`; an omitted `start` with a past `end` →
   `f"end {end!r} is before now"` (the stated-pair message would print `None`).
7. **Omitted bounds are edge-authored raw instants — a hint, not a promise.** `start` → `clock.now()`.
   `end` → the **folded reach end, read live**: `min` over the *requested* parameters of
   `reach(p)`'s T upper (the surface-specific fold, at the edge because the fold set is the
   request's). Resolution still serves `bounds ∩ the winner's live window`, so a stale read trims
   harmlessly (fact 7). **Why a real bound and not a huge sentinel** — the obvious simplification
   (resolution trims anyway, so any large `end` serves the same v1 response) is wrong on purpose,
   twice over: open-ended bounds are a deferred m4 form, and a sentinel delegates the upper edge to
   **each winner separately** — at the first diverging-reach parameter set (the second provider),
   a mixed request would come back in two lengths and break closed projection, where the `min`
   fold keeps the response one shape. The fold is the edge's seat for the mixed-reach policy
   [#30](../concerns.md#30-response-membership-under-runtime-degraded-fallback) deliberately keeps
   open; v1's fold is degenerate (one shared reach), which is exactly why the reason is recorded
   here rather than left readable only from the code. A canonical `Selection` also *records the
   ask* — the edge completes an unstated bound with the profile's truth, not with infinity.
   **Degenerate guard:** when `end` is omitted and the fold lands at or before
   the stated `start` (a `start` beyond reach), the edge authors `Interval(start, start)` — the
   single-instant ask — and **admission** answers `capability-mismatch`: the old Rule-3 sub-case
   surviving in snapped form, and the edge still never rejects on reach's word.
8. **The two align calls are recorded, not implemented** (2026-08-05; decisions of record in the
   [ticket](../tickets/01-0110-request-shaping.md)'s criteria): the two-fetch divergence is
   **accepted rare-and-loud for exactly one ticket** — no mitigation; retention follows directly in
   the queue and collapses the warm path; the cold-store residue belongs to 006's refill-scope
   decision ([#30](../concerns.md#30-response-membership-under-runtime-degraded-fallback)). And
   **the request side keeps two representations** — the edge authors `SelectionDomain`, `ground`
   stays a function; narrowing waits for the second request author
   ([#42](../concerns.md#42-two-request-representations-so-resolution-cannot-be-a-method)).
   Stage 4 cites m4's existing divergence pin; stage 5 re-confirms the judgement against shipped
   behaviour.

**Window assembly** (inside `build_selection`, replacing the `default_horizon` block and the
`"start/end not yet supported"` stub; the lat/lon range checks above it are unchanged):

```python
def build_selection(*, latitude, longitude, parameter_names, start, end,
                    clock, capability, table) -> Selection   # the full new signature

params = _resolve_parameters(parameter_names, envelope=capability.parameters, table=table)
if not params:                                       # empty served menu — before the reach fold
    raise CapabilityMismatch("profile serves no parameters")           # (decision 3)

start_i = _parse_bound(start) if start is not None else clock.now()    # implicit start = now, raw
if end is not None:
    end_i = _parse_bound(end)
    if start_i > end_i:                                                # raw ordering (decision 6)
        raise BadRequest(
            f"start is after end ({start!r} > {end!r})" if start is not None
            else f"end {end!r} is before now"
        )
else:
    reach_end = min(_t_upper(capability.reach(p)) for p in params)     # read LIVE — a hint
    end_i = max(reach_end, start_i)                  # start beyond reach → single-instant ask
                                                     #   admission answers (decision 7)
domain = SelectionDomain(axes={
    AxisName.X: RegularAxis(AxisName.X, longitude, _SPATIAL_STEP, 1, False),   # unchanged
    AxisName.Y: RegularAxis(AxisName.Y, latitude, _SPATIAL_STEP, 1, False),    # unchanged
    AxisName.Z: VantageAxis(AxisName.Z, _VANTAGE_Z),                           # unchanged
    AxisName.T: SnappedAxis(AxisName.T, Interval(start_i, end_i)),
})
return Selection(domain=domain, parameters=params)
```

`_t_upper(domain)` = `domain.axis(AxisName.T).extent.upper`, narrowed with an
`isinstance(…, datetime)` guard that **raises `TypeError`** on a non-datetime — the axis `extent`
is coordinate-generic, so this is `_iso_z`'s existing guard applied at the fold, keeping `pyright`
clean without a cast.
`build_selection`'s `envelope: Mapping[…]` parameter becomes the woven root **`capability`** (it
needs `reach`, and `capability.parameters` is the envelope it already used). `_resolve_parameters`
gains decision 3's empty-list rule before any lookup. `_horizon_hours` is **deleted** with its only
input. No `floor_to` import remains in the module.

## Flows

**Every request:** resolve `params` → parse bounds (datetimes only) and order on raw instants →
author the `SelectionDomain` (X/Y point, Z vantage, T snapped) → `Gateway.resolve` → intersective
admission (`serves`, per winner) → the winner grounds `bounds ∩ its live window` on its own
lattice, fetches, grounds again against the delivery, crops (all m4, untouched) → serialize.

**Failure surface:** `BadRequest` only for the purely syntactic — unparsable bounds, bare dates,
a backwards window (raw instants, implicit `start = now`), an explicitly empty `parameters` list.
`capability-mismatch` — a no-overlap window (admission's answer, including the decision-7
degenerate ask), an empty served menu, and m4's snapped-shape declines. `runtime-failure` —
divergent winner domains (decision 8 — pinned, accepted) and vendor garbage per the normalizer.
A *shorter* vendor delivery is **not** a failure (fact 8). No new error categories; resolution
trace remains [#14](../concerns.md#14-resolution-trace-and-observability), unowned here.

## Compatibility and rollout

- **A compatible contract change, named as such:** the MCP tool *schema* is unchanged
  (`start`/`end` were always declared); only semantics land. Previously any supplied `start`/`end`
  was rejected; now honored, and out-of-range bounds yield the **servable part** — the response's
  `valid_time` is the disclosure. The omitted-`end` window grows 168 → 384 ticks (fact 6),
  narrated in the tool description.

## Superseded approach (the clamp record)

The 2026-07-25 staging's decision 2, preserved as the decision trail; superseded the **same day**
by the Snapped-T mode ([m4](../tickets/done/01-0100-snapped-t-request-mode.md)). The edge was to
author the in-range window itself: each bound parsed to an *(instant, tick)* pair (`_Bound`);
**Rule 1** — ordering against `floor(now)` for the implicit start; **Rule 2** — clamp the
stated-or-default ticks into the servable range, the folded reach snapped *inward* onto the hourly

single stated tick when `end` was omitted) so **admission** answered `capability-mismatch`;
`count ≥ 1` by construction; plus an interleaving proof that the double clock read was benign.

clock races, per-input ordering rules, tick authorship without the winner's lattice — and the
align concluded window fitting belongs to **resolution**, where the winner's own grid supplies
anchor and step (`ground`/`clip`, built at m4). The recorded costs filed at the time — reach may
understate, and the mixed-reach fold policy deliberately open — remain filed at
