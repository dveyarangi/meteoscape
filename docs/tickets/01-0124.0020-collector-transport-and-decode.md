# The collector's database is reachable and its schema pinned

- **Status:** Ready
- **Type:** AFK
- **Depends on:** [config and secrets](./done/01-0123-config-secrets-degrade.md) (the connection
  string is a secret), [composition lifetime](./done/01-0116-composition-lifetime.md) (the seam this
  connection is held and released through — its first real holder)
- **Blocks:** [station observation serving](./01-0124.0030-station-observation-serving.md),
  [Mongo forecast-run archive source](./01-0134-forecast-run-archive-source.md) (both read through
  this transport).
- **Outcome:** Meteoscape can hold a read-only connection to the operator's collector database,
  release it with the composition, read the station registry, and decode either observation schema
  into canonical values — with the schema pinned by fixtures sampled from real documents.

## Parent

Second slice of the [Mongo obs source](./01-0124-mongo-obs-source.md), carved at its serving plan
(2026-08-22): the *acquire and decode* half, which carries
[#45](../concerns.md#45-the-collector-schema-is-a-contract-meteoscape-depends-on-but-does-not-own)'s
whole mitigation set and can be verified without any algebra. The parent holds the align
resolutions; [serving](./01-0124.0030-station-observation-serving.md) follows with the producer.

## What to build

The first non-HTTP transport, and the vendor face over it:

- **A held connection.** One `AsyncMongoClient` per composition, constructed synchronously (its
  constructor is non-blocking and binds no loop) and released through the structural `Closeable`
  facet — the [0116](./done/01-0116-composition-lifetime.md) seam's **first real holder**, so this is
  where "the seam fits" stops being an argument and becomes a test. Its URI is read through the
  generic `SecretSlot` mechanism at `METEOSCAPE_COLLECTOR_OBS_URI`.
- **Read-only by construction**, pinned by a guard: no write, update, or insert operation reaches
  the client.
- **Two reads, both value-typed** — the vendor face interprets nothing and speaks no `Domain`,
  `Provenance`, or `Clock` ([edge/provider.md](../edge/provider.md)): the station registry (each
  station's id, place, name, owning network, and which canonical parameters it writes) and one
  station's observation series over a window.
- **One canonical mapping over both schemas**, discriminated per document by its `source` field —
  the regional network's `raw` + `method` documents and the flat legacy ones. Wind arrives as
  speed and direction and decodes to `wind_u` / `wind_v` through the existing joint-tap machinery
  (**confirmed 2026-08-22** against the retraction in
  [serving](./01-0124.0030-station-observation-serving.md): [parameters.md](../parameters.md)
  defines `wind_speed` as derived `= hypot(u, v)`, and TWC already decodes the same measured pair);
  units arrive canonical (measured at the align), so no conversion belongs here.
- **Tick labels are floored onto the hour** (**resolved 2026-08-22 plan, measured**): the archive is
  not one hourly lattice — each station's older documents are labelled `HH:20` and its newer ones
  `HH:00`, with the changeover date differing per station. The family derives one `RegularAxis` from
  the delivered ticks and faults on anything off its declared step, so a window spanning a station's
  changeover would fault. Flooring at decode makes the whole archive one hourly lattice; the label
  then means *the hour the reading was taken in*, which the scattered `observed_at` offsets show is
  already true post-changeover. The enlarged convention error is recorded at
  [#48](../concerns.md#48-a-tap-cannot-declare-where-its-value-sits-relative-to-the-tick).

**Out of scope:** capability, geometry, provenance stamping, and serving — all
[the next slice](./01-0124.0030-station-observation-serving.md)'s; the forecast collections
([archive source](./01-0134-forecast-run-archive-source.md)); any write path or live station
endpoint, permanently ([#45](../concerns.md#45-the-collector-schema-is-a-contract-meteoscape-depends-on-but-does-not-own),
[#26](../concerns.md#26-provider--calculator-plugin-scaffolding)).

## Acceptance criteria

- [ ] A composition holding a collector connection releases it through `Gateway.aclose()`, pinned by
      a connection-liveness check rather than a mock call count — the 0116 seam's first real holder.
      **Resolved (2026-08-22 plan): proven through `compose` with a test catalogue.** A
      composition's release set is built only from the two construction sites `compose` hands the
      `Gateway` — `SourceRegistry.providers` and `StoreFactory.created` — and the first is filled
      only by `manifest.build`, so *only a `Provider` can hold this connection*. The producer is
      [the next slice](./01-0124.0030-station-observation-serving.md)'s, so this slice proves the
      criterion end to end through `compose` with a **test catalogue** whose manifest builds the
      real transport behind the existing closeable test producer: real client, real release path,
      real liveness check, and nothing dead added to `src`.
- [ ] ~~A profile declaring the collector without its secret refuses startup, as any keyed offering
      does.~~ **Moved (2026-08-22 plan) to
      [station observation serving](./01-0124.0030-station-observation-serving.md)** — the refusal
      is the binder reading a registered `ProviderManifest`'s `SecretSlot`, and a manifest's `build`
      must return a `Provider`. The slot's *name* (`METEOSCAPE_COLLECTOR_OBS_URI`) is still this
      slice's, since the transport reads the URI; only its registration moves.
- [ ] No write reaches the client, pinned by a guard that fails if a write operation is issued —
      not by reading the code.
- [ ] Both observation schemas decode to the same canonical parameters through one mapping, pinned
      by integration fixtures sampled from real documents; a collector-side schema change fails the
      suite rather than silently misreading at runtime.
- [ ] A station that writes no value for a canonical parameter yields that parameter's absence, not
      a null-filled series.
- [ ] The registry read reports, per station, its place, its display name, its owning network, and
      which canonical parameters it writes — the facts the next slice turns into geometry and
      provenance.
