## What to build

The family's second geometry
([one timeline algebra](./done/01-0114-timeline-shape-generalization.md)): a producer
declaring the collector's stations as a scatter and serving each one's hourly series.

- **`ArchiveAxis`** — the past-facing sibling of `RollingAxis`, beside it in `cadence.py` since both
  are clock-anchored `valid_time`: its lower is the archive floor and its upper rides the clock, so
  the window *grows* rather than rolling. A rolling window cannot express it — `max_lead` is a
  length and its base moves forward — and a static axis would stop admitting recent hours between
  registry refreshes.
- **Declared geometry**: one `ScatterDomain` per canonical parameter, over the places whose stations
  write it, sharing that `ArchiveAxis` and the surface Z cell.
- **Grounding by place** — a request is admitted only at a member place, and grounding then runs
  against **that place's own separable geometry**, which the scatter's shared T and Z supply with
  the matched place as X/Y. This is why the producer needs no change to `ground`: a scatter is a set
  of point timelines, and choosing the place turns it back into the shape the family already serves.
- **Discovery before the request**: `Capability.origins` pairs each place with the origin that would
  serve it — the network, the method, and the station's name or network id — read from the registry
  snapshot, and equal to what serving later stamps.
- **Signing at serve**: authority and method come from the documents themselves, the station
  identity from the record that addressed the read; `issue_time` is absent and the value never
  expires.
- **A registry that stays current**: the snapshot re-reads on the serving path once its interval has
  passed, so a station added to the collector becomes servable without a restart. The family's
  refresh extension point is where this lives.

Composed **standalone** — an obs-only profile tested through `Gateway`; no pilot composition root,
and no shared parameter beside a forecast producer, which the dominance fold still refuses
(→ [obs+forecast reach composition](./01-0137-obs-forecast-reach-composition.md)). Observed wind is
declared as measured speed and direction rather than decoded to components: honest to the
instrument, and it keeps the scatter out of the wind calculator's input fold until that fold lands.

## Acceptance criteria

- [ ] A request over an archived window at a registered station serves the hourly observation series
      for the parameters that station writes, signed with the network, the method, and the station.
- [ ] A request at an unregistered place declines as capability; an admitted window whose overlap
      with retained data is empty fails as `capability-mismatch` at serve — never served empty or
      padded. Holes inside a served overlap are nodata.
- [ ] A bounded-T request grounds against the scatter reach — the case a non-separable declaration
      would otherwise refuse, and the reason the family's grounding is an extension point.
- [ ] `Capability.origins` pairs every servable place with its declared origin, and a subsequent
      serve at that place stamps the same identity.
- [ ] The declared window's upper advances with the clock, pinned by advancing a fake clock rather
      than by rebuilding the producer.
- [ ] A station added to the collector's registry becomes servable without a process restart, pinned
      by advancing a fake clock past the re-read interval — not by restarting the fixture.
