## What to build

~200–280 raw lines (003a-scale). Read-back is the substance: **relabel, then fold** — a record's
count-1 X/Y/Z axes are rewritten to the answer geometry (values and provenance untouched; the
claim that a value measured *here* answers *there*, carrying `TODO(0117)`), after which the
existing carrier fold crops T and merges. The crop engine refuses to make that claim itself —
`resample` raises *"requires Reservoir homogenization"* — and that refusal is a guard to keep, not
a gap to widen (RFC 0014 d.2 / fact 7).

- `Reservoir.project` runs the pipeline (*amended 2026-08-09: the report verb dissolved; the
  store takes raw asks*): **load holdings** (`store.project(selection)` — the store translates
  onto its boxes internally) → the **serve-vs-refetch gate as `Reservoir` policy** — a parameter
  refills when *absent*, *expired* (provenance `summary` against the `Reservoir`'s injected
  clock), or — *only where the request bounds T* — its held window does not *cover* the required
  one (request T ∩ child reach; covers-or-refetch-whole). A boundless ask has no extent to cover,
  so freshness alone governs there → **refill** the missing/stale parameters in one
  `child.project(store.quantize(request))` call (the store-authored fetch-order — `quantize`'s
  only public use; ask narrow, answer natural, store absorbs) → `assimilate` → reload →
  read-back: relabel matched native cells onto the handed shape and crop to the request →
  parent, *What to build* and *Refill scope*.
- The `Reservoir` gains an injected `Clock` for the freshness gate, so the `Weaver` and
  `wire_source` carry one too (the `Store` contract stays clockless — freshness is the reader's
  policy). The stores themselves were already wired inert at slice 3.
- The e2e's second-call **re-fetch assertion** (documenting no-retention) flips here: its
  `route.call_count` goes **4 → 1** across the two requests — the cold trip carries the provider's
  whole offering, so it also warms the Calculator's inputs, and the repeat serves from the root
  store (RFC 0014 fact 8). Two sibling e2es move with it: the snapped-selection test's vendor-query
  assertions relocate to the answer geometry, while the out-of-range test survives untouched
  (RFC 0014 d.6).
- **The vendor query widens** — the refill asks `ANY` on T, so a cold request costs the provider's
  whole live window instead of its own slice, bought back by every later request in that window
  costing nothing. Served answers are unchanged (read-back crops), but the Provider surface sees
  it, so [edge/provider.md](../edge/provider.md) records it with the pending-006 flip.
- Landing docs: the provider edge record's pending-006 block flips to current-state (ADR-0001's
  answer-discipline sentence lands earlier, with the
  [carrier slice](./done/01-0115.0020-multidomain-carrier-timeline.md) that first exercises it).

## Acceptance criteria

- [ ] The pipeline is live in both positions (the stores themselves were wired inert at slice 3);
      a Source's units stay keyed by the **native** Z cell, the root's by the request's vantage.
- [ ] Read-back answers on the request's own geometry: a value held at a grid tick and a native
      height is returned addressed to the asked point and vantage, with its values and provenance
      unchanged — and the relabel is a single marked site (`TODO(0117)`), not a loosened crop.
- [ ] A parameter the child does not serve is **omitted** from the answer, not raised on (the
      read-back folds over what is *held*, never over what was asked); a request where the child
      serves **nothing** is a `CapabilityMismatch`, matching the Arbiter's verdict.
- [ ] A fully-fresh repeat request is served with **no** provider call (0112's day-anchoring makes
      same-day full-horizon repeats identical).
- [ ] A request whose Z differs from a prior one **reuses** stored native units rather than
      refetching.
- [ ] A stone-cold mixed request (direct parameters + calculator inputs) issues **one** vendor
      fetch; the Calculator's input `Selection` is served from the store; same `issue_time` across
      all assembled parameters — the Calculator's inputs are fresh in the store, and a boundless
      ask has no coverage to fail (RFC 0014 d.5).
- [ ] A temporal miss or window-extension refetches the **whole unit** single-origin end-to-end
      (old window discarded; the refetched unit lands the provider's full live timeline).
- [ ] The `Arbiter` never serves stale entries; the retention interval only bounds memory.
- [ ] Per-unit freshness is honored as `Reservoir` policy: an unexpired unit serves with no trip,
      an expired one triggers refill (differing expirations mocked — a single-cadence source's
      units age together); a held window that does not cover the required one refetches the whole
      unit (covers vs extension vs disjoint — moved here from slice 3, 2026-08-09).
- [ ] Mocked-transport integration tests cover fresh-serve, per-parameter refill (mocked
      expirations), and whole-unit single-origin refetch.
