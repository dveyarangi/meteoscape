Implementation plan for [003c](../tickets/01-0110-request-shaping.md). The window *semantics* (flooring,
inclusive `end`, reach-end default) were settled by the
ticket's two aligns (sessions 0013/0014) and are restated here only where an implementation fact
pins them; the decisions of record stay in the ticket and
[ADR-0007](../adr/0007-capability-carries-its-domain.md).

**Scope in one line:** the MCP edge turns optional `start`/`end` strings into the exact hourly
request lattice, **clamping** stated bounds into the live folded reach (the omitted-`end` default
generalized to both edges), narrates the relative horizon, and `Settings.default_horizon` is
deleted — all inside the surface adapter; no engine, provider, or manifold change (plus one
`ceil_to` helper in `clock.py`).

## Facts that shape the implementation (verified 2026-07-25)

1. **`validate_calculators` is already `weave`'s first step** (`nodes/weaver.py`, before any Store
   allocation; `tests/deterministic/test_server.py` asserts the startup `CompositionError`). The
   ticket's compose()-step criterion is annotated **already landed**; this RFC makes **no change**
   there.
2. **The default window is a constant 384 ticks.** Open-Meteo declares
   `CadenceDef(cadence=1 h, publication_latency=1 h, max_lead=16 d)`
   (`providers/open_meteo.py`). With Δ = 1 h, the run anchor is always `floor(now, 1 h) − 1 h`, so
   `count = (A + 16 d − floor(now,1h)) / 1 h + 1 = 384` regardless of `now`. Deterministic tests
   may assert 384, **computed from `CADENCE`**, never hardcoded without the derivation comment.
3. **Admissible-by-construction is boundary-inclusive**: `Interval.contains` uses `<=` on both
   bounds and `RegularAxis.matches` is extent containment, so a request whose T upper equals the
   reach upper is admitted, and the request anchor `floor(now,1h) ≥ A` always.
4. **The narrated horizon is invariant**: a `RollingAxis` extent is `[A, A + max_lead]`, so
   `extent.upper − extent.lower = max_lead` no matter when it is read — which is what makes the
   relative narration ("out to N ahead of the latest model run") true for the process lifetime.
5. **`datetime.fromisoformat("2026-07-20")` silently parses as midnight**, so the datetimes-only
   rule (decision 5) still needs the `date.fromisoformat` probe **first** — succeeding means the
   caller sent a bare date, which is rejected with guidance; only on the probe's `ValueError` fall
   through to `datetime.fromisoformat`.
6. **Python 3.14 `fromisoformat` accepts the `Z` suffix** (no `.replace("Z", ...)` needed for
   inputs; the payload serializer's existing `_iso_z` is unchanged).
7. **The double clock read is benign — proven, not lucky.** The clamp path reads the clock twice
   (`now_tick` from `now₁`; `reach(p)` resolves its `RollingAxis` against `now₂`). If the hour
   rolls between the reads, the default window comes out one tick longer (385), but its last tick
   is then *exactly* `A + max_lead` and containment is inclusive — still admissible. The anchor
   can advance at most one hour between reads while `A` trails by ≥ 1 h, so the clamp's
   containment survives every interleaving. Do not "fix" this with a lock or a threaded
   timestamp — a single-read refactor is not even possible (`RollingAxis` reads its own injected
   clock by design). Deterministic tests are immune (`StoppedClock`).
8. **`clock.py` gains `ceil_to`, the peer of `floor_to`** (smallest step-aligned instant ≥ the
   moment, epoch-anchored) — needed by the inward snap. For v1 it is a no-op on the reach bounds
   (Δ = 1 h keeps `A` hour-aligned), but the snap is what keeps authorship correct for any future
   non-hour cadence.

## Design decisions (planned 2026-07-25)

1. **The compose()-validation criterion is satisfied by existing code** (fact 1). Ticket annotated;
   no double call is added.
2. **Out-of-range windows clamp to the served range; `bad-request` is purely syntactic (aligned
   2026-07-25 — supersedes this RFC's earlier two-layer rejection rule; the ticket criterion,
   v1-requirements §Time axis, and [#30](../concerns.md#30-response-membership-under-runtime-degraded-fallback)
   are realigned).** Closed projection forbids partial-time responses (a parameter covers
   `sel.domain` whole or drops whole), so "serve whatever is in range" has exactly one home: the
   **edge authors the in-range window** — the omitted-`end` reach default generalized to both
   edges and to out-of-range stated bounds. Nulls-padding was considered and stays dissolved on
   [#30](../concerns.md#30-response-membership-under-runtime-degraded-fallback)'s recorded grounds
   (a padded tail is indistinguishable from measured absence). The rule set, exhaustively:
   - **Rule 1 — ordering, raw instants:** (stated `start` instant, or **`floor(now, 1h)`** when
     omitted — the tick the default anchors at, so an `end` inside the current hour stays valid) >
     the stated `end` instant → `bad-request`. A backwards window is malformed as stated,
     including the implicit-start form ("from now through yesterday"). With datetimes only
     (decision 5), tick ordering **follows** from raw ordering by flooring monotonicity — the
     former stated-tick rule (the date-edge equality case) is provably dead and deleted.
   - **Rule 2 — clamp:** `anchor = max(stated-or-default start tick, first_servable_tick)`,
     `end_tick = min(stated-or-default end tick, last_servable_tick)` — servable ticks per the
     authorship steps in §Code shapes (folded reach snapped **inward** onto the hourly lattice).
   - **Rule 3 — no overlap:** post-clamp `end_tick < anchor` ⟺ the stated window lies wholly
     outside the folded reach (well-formed but unservable). Two sub-cases: **both bounds stated**
     (e.g. history) → build the stated window verbatim (ordered, by Rule 1 + monotonicity);
     **`end` omitted** (`start` beyond the reach end — there is no stated end to restore) → build
     a **single tick at the stated `start`** (the old degenerate rule surviving as this
     sub-case). Either way **admission** answers `capability-mismatch` — the edge never rejects on
     reach's word; it clamps to it and hands the hopeless case to the authority.
   - `count ≥ 1` is an invariant by construction on every path (Rules 1 and 3).
   - **Accepted, recorded costs** (both filed at [#30](../concerns.md#30-response-membership-under-runtime-degraded-fallback),
     one trigger — the first diverging-reach parameter set): reach may *understate* (a regional
     producer reaching further gets its extra hours trimmed); and the **mixed-reach fold policy is
     deliberately open** — min-fold clamping shrinks the whole bundle to its weakest parameter,
     max+dropout preserves the strong one; v1's fold is degenerate (one shared reach), so nothing
     is decided here by accident.
   - Deliberate consequences worth naming: an early `start` returns data from the servable edge
     instead of a mystery mismatch; `end` in the current hour with `start` omitted is one
     current-conditions tick; and the response's `valid_time` **is** the clamp's disclosure — the
     caller sees exactly what was served.

3. **An explicitly empty `parameters` list is `bad-request`.** `parameters=[]` resolves to an
   empty frozenset today (harmlessly empty Coverage), but 003c's reach fold `min(...)` over zero
   parameters would raise a naked `ValueError` on the omitted-`end` path. An empty request is
   meaningless; `None` keeps meaning "all served". Message: `"parameters must not be empty; omit
   it to get all served parameters"`.

4. **The 384-tick default is the first request to touch the conservative-cadence edge — probed
   live, with the contingency owned by #18.** The default window ends exactly at `A + max_lead`,
   a boundary no 168 h request ever approached, and
   [#18](../concerns.md#18-clock-anchored-footprint-fidelity) accepts "occasional edge nodata"
   from the conservative `{Δ, L}` estimate. Two vendor behaviors are possible there and neither is
   tested: trailing nulls (fine — honest nodata, and the parity reference shows the same nulls) or
   a vendor **400/clamped response** (breaks every default request). The **post-003c live parity
   run** (`uv run pytest tests/parity`) is promoted to the explicit acceptance probe for the new
   default (stage 5); if the vendor rejects or clamps the edge, the fix is **cadence tuning**
   (`max_lead` / `publication_latency` — the config facts #18 owns), never edge-code special
   cases.

5. **Bounds are ISO datetimes only — bare dates are rejected loudly (aligned 2026-07-25; reverses
   the session-0013 day-cell rule, struck in the ticket).** The 0013 rationale — a date read as
   midnight silently returns one hour of "through the 20th" — ruled out *silent* midnight; loud
   rejection honors it equally while deleting the day-cell semantics that produced the edge holes
   (the day-end ordering edge, the reversed-adjacent-dates tick rule, the date-vs-midnight
   ambiguity, the week-date quirk — the same probe now rejects week dates too). Detection is
   unavoidable either way (fact 5), so only the day-cell branch dies. Accepted cost: one
   self-healing round trip for an agent that writes `"start": "2026-07-26"` — the `bad-request`
   message carries the fix (`use a datetime like 2026-07-26T00:00`) and the narration states
   datetimes.

**Bound parsing** — one private shape carries both halves decision 2 needs:

```python
@dataclass(frozen=True)
class _Bound:
    instant: datetime   # the malformed-check reference (raw semantics)
    tick: datetime      # the lattice half: the hourly tick this bound contributes

def _parse_bound(raw: str) -> _Bound:
    # 1. date.fromisoformat(raw) succeeding ⇒ a bare date (incl. week dates) → BadRequest
    #    (decision 5): f"bare dates are not accepted; use a datetime like {raw}T00:00"
    # 2. else datetime.fromisoformat(raw); ValueError → BadRequest(f"unparsable start/end: {raw!r}")
    #      naive → replace(tzinfo=UTC); aware → astimezone(UTC)
    #      instant = the parsed instant, tick = floor_to(instant, 1 h)   (both start and end:
    #      `end` is inclusive of the cell containing it — same flooring, per the ticket)
```

**Window assembly** (inside `build_selection`, replacing the `default_horizon` block and the
`"start/end not yet supported"` stub):

```python
# -- ordering (decision 2, Rules 1-2): bad-request is purely syntactic --
start_b = _parse_bound(start) if start is not None else None
end_b   = _parse_bound(end) if end is not None else None
now_tick = floor_to(clock.now(), _HOUR)
start_ref = start_b.instant if start_b else now_tick        # implicit start = the default's tick
if end_b is not None and start_ref > end_b.instant:
    raise BadRequest(f"start is after end ({start!r} > {end!r})")            # Rule 1
# (no tick-ordering rule: datetimes-only makes tick order follow from raw order — decision 5)

# -- servable range (authorship steps 1-4): folded reach, snapped INWARD onto the lattice --
lower = max(_t_lower(capability.reach(p)) for p in params)                    # read LIVE
upper = min(_t_upper(capability.reach(p)) for p in params)
first_servable = ceil_to(lower, _HOUR)     # smallest lattice tick >= lower  (v1: no-op, A is aligned)
last_servable  = floor_to(upper, _HOUR)    # largest  lattice tick <= upper

# -- clamp (Rule 3) --
stated_anchor = start_b.tick if start_b else now_tick                         # omitted start = now
stated_end    = end_b.tick if end_b else last_servable                        # omitted end = reach end
anchor   = max(stated_anchor, first_servable)
end_tick = min(stated_end, last_servable)

# -- no overlap (Rule 3): stated window wholly outside reach -> admission answers --
if end_tick < anchor:
    if end_b is None:
        anchor, end_tick = stated_anchor, stated_anchor    # start beyond reach: single stated tick
    else:
        anchor, end_tick = stated_anchor, stated_end       # verbatim; ordered by Rule 2
count = (end_tick - anchor) // _HOUR + 1                   # >= 1 on every path -> capability-mismatch
                                                           #    resolves it when Rule 3 fired
```

`_t_upper(domain)` = `domain.axis(AxisName.T).extent.upper`. `build_selection`'s `envelope:
Mapping[...]` parameter becomes the woven root **`capability`** (it needs `reach`, and
`capability.parameters` is the envelope it already used); the X/Y/Z axes are unchanged.
`_resolve_parameters` gains one rule (decision 3): an explicitly empty `names` list raises
`BadRequest("parameters must not be empty; omit it to get all served parameters")` before any
lookup. `_horizon_hours` is **deleted** with its only input.

Parsing note: Python ≥3.11 `date.fromisoformat` also accepts ISO **week dates**
(`"2026-W30-1"`); under decision 5 the same probe rejects them as bare dates — one test pins
that.

Empty-set note: an empty **resolved** parameter set — reachable only through an empty served menu
(a no-provider profile; the `test_server_smoke` shape), since an explicitly empty list is already
`bad-request` (decision 3) — raises `CapabilityMismatch("profile serves no parameters")` at the
edge **before** the reach fold, which is undefined over zero parameters. Literally the right
category ("no producer declares it"), and a server-configuration condition, not a caller error.
A smoke-level test pins it.

**Narration** — built once at `build_mcp_app` (frozen for process lifetime, per the ticket):

```python
def _narrated_horizon(capability, menu) -> timedelta:
    # min over the exposed menu of (reach(p).T extent length) — invariant (fact 4)
    return min(_t_len(capability.reach(p)) for p in menu)

def _format_horizon(td) -> str:
    hours = td // _HOUR
    return f"{hours // 24} days" if hours % 24 == 0 else f"{hours} hours"   # v1: "16 days"
```

Description text (replacing the `Default window:` and `reserved` sentences):

```text
Hourly point forecast for a latitude/longitude.
Served parameters: {served}.
Horizon: out to {N} ahead of the latest model run.
Optional `parameters` selects a subset (default: all served).
Optional `start`/`end` bound the hourly window (ISO 8601 datetimes, UTC; naive times read
as UTC; bare dates are not accepted — give e.g. 2026-07-20T00:00; `end` is inclusive;
omit `start` to begin now; omit `end` to run to the full horizon; bounds outside the
served range are clamped to it — the response's `valid_time` shows the window actually
served).
```

An empty menu skips the horizon sentence (`min()` over nothing must not raise at startup; the
`"(none)"` served-parameters case already exists).

## Flows

**Every request:** resolve `params` → parse (datetimes only) and order (Rule 1) → read the folded
reach **live**, snap inward to the servable tick range → clamp the stated-or-default bounds into
it (Rule 2) → Selection → admission (`serves`) re-confirms containment against each producer's
rolling footprint. An overlapping request is **admissible by construction** (the containment
chain in §Code shapes); a zero-overlap request goes through verbatim (Rule 3) and admission
answers `capability-mismatch`.

**Failure surface:** `BadRequest` only for unparsable bounds, bare dates (decision 5), backwards
windows (Rule 1), and an explicitly empty `parameters` list (decision 3). A zero-overlap window is
`capability-mismatch` via admission. A vendor that serves less than the declared reach at the
16-day edge surfaces as the provider's **length-check `RuntimeFailure`** (the concern-#31 site in
`_assemble`) — the decision-4 symptom, fixed by cadence tuning, never by edge code. No new error
categories, no logging changes (resolution trace remains
[#14](../concerns.md#14-resolution-trace-and-observability), unowned here).

## Compatibility and rollout

- **Caller-visible behavior change:** previously any supplied `start`/`end` was rejected; now
  honored, and out-of-range bounds **clamp** to the served range instead of failing — the
  response's `valid_time` discloses the served window. The omitted-`end` window grows 168 → 384
  ticks (fact 2) — narrated in the tool description; agents reading the description get the new
  truth, and `parameters`/response shape are untouched.
- The MCP tool *schema* is unchanged (`start`/`end` were always declared); only semantics land.
- No migration: `METEOSCAPE_DEFAULT_HORIZON` env (if any operator set it) becomes inert —
  `extra="ignore"` on `Settings` swallows it silently, which is acceptable for a knob that never
  shipped in a release.

## Scope limits and follow-ups

- **No `step` input, no aggregation** — hourly-only stands ([#15](../concerns.md#15-coarser-grid-resampling-and-aggregation-semantics)).
- **No alias desugaring / exact-mode Z** — deliberately excluded by the ticket (session 0013).
- **Location-blind narration** — one number for the whole globe; the per-location truth is the
  deferred capabilities-introspection tool ([#29](../concerns.md#29-narrated-reach-what-a-profile-promises)).
- **Parity interaction:** the live parity check requests the default window, so after 003c it
  compares 384 ticks instead of 168 — within Open-Meteo's own 16-day product, no reader change
  (its `start_hour`/`end_hour` come from the payload). Only the `build_mcp_app` call site changes.
- **`retention_interval` and `store_spatial_step`** stay (they belong to 006), only
  `default_horizon` dies.
